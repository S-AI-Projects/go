# Strain Maintenance & Mutation Analysis Guide

This document records the contract, mutation testing analysis, file classifications, and proposed test cases for `exercises/practice/strain`.

---

## 1. The Strain Contract

The `strain` exercise defines generic operations for filtering collections:

```go
func Keep[T any](list []T, fn func(T) bool) []T
func Discard[T any](list []T, fn func(T) bool) []T
```

### Contract Guarantees
1. **Predicate Fidelity**:
   - `Keep` includes every element where `fn(elem) == true`.
   - `Discard` includes every element where `fn(elem) == false`.
   - For all inputs: `len(Keep(list, fn)) + len(Discard(list, fn)) == len(list)`.
2. **Order Preservation**:
   - Filtered elements must appear in the exact relative order of the input.
3. **Input Immutability**:
   - The input slice must remain completely untouched. Slices must not be modified in-place or have their underlying backing arrays overwritten.
4. **Boundary Handling**:
   - Empty or `nil` slices must return an empty slice (or `nil`) without panic.

## 3. Deliberate Mutation Analysis

Two deliberate mutations were tested in isolated scratch copies against the canonical test suite:

### Mutant 1: Condition Inversion Mutant
- **Location**: `Keep` in `.meta/example.go`.
- **Change**: Inverted the selection condition from `if fn(entry)` to `if !fn(entry)`.
- **Rejecting Existing Case**: `TestInt/keeps_everything` (UUID `f535cb4d-e99b-472a-bd52-9fa0ffccf454`).
- **Assertion Failure**:
  ```text
  strain_test.go:23: Keep([]int{1, 3, 5}, "func(x int) bool { return  true }") = []int{}, want []int{1, 3, 5}
  --- FAIL: TestInt (0.00s)
      --- FAIL: TestInt/keeps_everything (0.00s)
  ```
- **Smallest Rejecting Input**:
  - Input: `[]int{1}`
  - Predicate: `func(x int) bool { return true }`
  - Expected: `[]int{1}`
  - Mutant Result: `[]int{}`

### Mutant 2: In-Place Backing Array Mutation
- **Location**: `Keep` in `.meta/example.go`.
- **Change**: Changed allocation `result := []T{}` to slice re-slicing `result := list[:0]`.
- **Rejecting Existing Case**: `TestInt/keeps_first_and_last` (UUID `92694259-6e76-470c-af87-156bdf75018a`).
- **Assertion Failure**:
  ```text
  strain_test.go:20: Keep([]int{1, 2, 3}, "func(x int) bool { return  x % 2 == 1 }") modified the input data; input data should not change
  --- FAIL: TestInt (0.00s)
      --- FAIL: TestInt/keeps_first_and_last (0.00s)
  ```
- **Smallest Rejecting Input**:
  - Input: `[]int{1, 2}`
  - Predicate: `func(x int) bool { return x % 2 == 0 }`
  - Expected: `[]int{2}`, and input remains `[]int{1, 2}`
  - Mutant Result: Modifies `input[0]` in place.

## 4. Proposed Minimal Diagnostic Case

While the existing suite successfully rejects the condition inversion mutant with `keeps_everything` (`[]int{1, 3, 5}`), the minimal diagnostic input of length 1 isolates single-element retention:

```json
{
  "description": "keep on single element matching list returns single element",
  "property": "keep",
  "input": {
    "list": [1],
    "predicate": "func(x int) bool { return true }"
  },
  "expected": [1]
}
```

This case serves as a compact diagnostic baseline for contract verification. Note that the reference implementation correctly passes this contract without modification.
